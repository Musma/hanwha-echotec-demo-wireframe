# 상태 UI 가이드 — Loading · Empty · Error

> 한화오션에코텍 물류Twin · v1.1 · 2026.07
> 대상: **UI/UX 디자이너** · 쓰는 시점: 화면 설계 · 시안 리뷰
> 색·타이포·모션 값이 충돌할 경우 **물류Twin Design System 토큰이 우선**한다.

우리가 시안으로 그리는 화면은 대부분 **데이터가 잘 들어온 상태(Happy path)** 하나다. 그런데 사용자가 실제로 만나는 화면의 상당수는 **기다리는 중이거나, 비어 있거나, 실패한 화면**이다. 이 문서는 그 세 화면을 **디자이너가 무엇을 기준으로 판단하고, 무엇을 산출물로 넘겨야 하는지** 정리한 것이다.

---

## 01. 사용자는 기다림을 이렇게 느낀다

로딩 UI의 목적은 "속도를 빠르게" 하는 게 아니라 **불확실성을 없애는 것**이다. 사용자가 불안해지는 순간은 느릴 때가 아니라 **무슨 일이 일어나는지 모를 때**다.

**사용자가 불안해지는 신호**

- 눌렀는데 아무 반응이 없다 → 다시 누른다
- 화면이 통째로 하얘졌다 → 실패했다고 판단
- 인디케이터가 번쩍하고 사라졌다 → 오류로 착각
- 언제 끝나는지 모른다 → 새로고침

**체감 시간을 줄이는 방법**

- 결과의 **형태를 미리 보여준다** (스켈레톤)
- 기다리는 동안 **다른 걸 만질 수 있게** 둔다
- 진행 **단계를 말로** 알려준다
- 기다림을 **아예 없앤다** (즉시 반영 후 정정)

> 현장 환경을 전제로 판단한다. 야외 직사광선, 장갑 착용, 불안정한 무선망.
> **화면이 조금 느린 것보다, 무엇이 진행 중인지 모르는 것이 훨씬 큰 사고로 이어진다.**

## 02. 화면 하나에 그려야 할 상태 세트

시안 산출물의 **최소 단위는 화면 1장이 아니라 상태 4장**이다. 데이터를 그리는 영역이 있는 화면은 예외 없이 아래를 함께 만든다.

| # | 상태 | 내용 |
|---|---|---|
| 01 | Loading | 기다리는 중 |
| 02 | Success | 데이터가 있음 |
| 03 | Empty | 비어 있음 (4유형) |
| 04 | Error | 실패함 |

여기에 더해 **데이터가 많은 경우 / 글자가 아주 긴 경우**도 함께 확인한다. 지번명이 3줄로 늘어나거나 목록이 500건일 때 레이아웃이 무너지는지는 시안 단계에서만 잡을 수 있다.

> **가장 흔한 사고** — 상태 시안을 안 넘기면 개발자가 임의로 만든다. 그 결과 화면마다 로딩 표현이 달라지고, 빈 화면은 "데이터 없음" 한 줄이 되며, 오류는 서버 메시지가 그대로 노출된다. **이건 개발 이슈가 아니라 디자인 누락이다.**

## 03. 로딩 패턴 고르기 — 세 가지 질문

### Q1. 얼마나 걸리나?

| 예상 소요 | 그려야 할 것 |
|---|---|
| ~1초 | 아무것도 그리지 않는다. 버튼 pressed 상태로 충분 |
| 1~5초 | 스켈레톤(최초) 또는 스피너(갱신) |
| 5~30초 | 프로그레스 + 진행 단계 문구 + **취소 버튼** |
| 30초 초과 | 기다리게 하지 않는다. "완료되면 알림" 안내 후 화면 해제 |

> 소요 시간은 추측이 아니라 개발팀에 물어본다. "이 조회 보통 몇 초 걸려요?" 한 마디로 패턴이 정해진다.

### Q2. 기다리는 동안 사용자가 할 일이 남아 있나?

남아 있으면 **그 부분은 절대 덮지 않는다.** 차단 범위는 "예쁨"이 아니라 "지금 무의미해진 영역"으로 정한다.

| 차단 범위 | 쓰는 경우 | 물류Twin 사례 |
|---|---|---|
| 화면 전체 | 앱 전체가 멈춰야 할 때만. **남발 금지** | 로그인, 로그아웃 |
| 영역(섹션) | 테이블·맵만 갱신. 필터는 계속 만질 수 있어야 함 | 지번 목록 조회 |
| 컨트롤 하나 | 버튼·셀렉트 범위 | 저장 버튼 |
| 상단 진행바 | 화면 이동. 막지 않고 알리기만 | 메뉴 전환 |
| 차단 없음 | 사용자가 기다리지 않는 작업 | 장비 위치 자동 갱신 |

### Q3. 끝이 언제인지 보여줄 수 있나?

- **퍼센트를 안다** → 프로그레스 바
- **단계만 안다** → "2/3 지번 매핑 중" 스텝 표기
- **아무것도 모른다** → 스피너

10초를 넘는 작업에서 스피너만 도는 것과 단계를 말해주는 것은 체감 차이가 매우 크다. **가능하면 단계를 만들어 달라고 요청할 것.**

### 3-1. 스켈레톤 vs 스피너

**스켈레톤 — 3가지 모두 맞을 때**

- 화면에 처음 들어온 순간이다
- 결과가 어떤 모양일지 우리가 안다
- 1초 이상 걸린다

**스피너 — 다음 경우**

- 이미 데이터가 떠 있는데 다시 조회한다
- 결과 모양을 예측할 수 없다
- 영역이 좁다 (버튼, 셀, 아이콘)

#### 시안에서 자주 나오는 실수

- **결과와 모양이 다른 스켈레톤** — 실제 데이터가 뜰 때 레이아웃이 튄다. 스켈레톤은 **실제 컴포넌트를 복사해서 회색으로 바꾼 것**이어야 한다
- **재조회할 때도 스켈레톤** — 보고 있던 데이터가 사라진다. 기존 데이터를 흐리게(불투명도 50%) 두고 스피너를 올리는 것이 정답
- **화려한 shimmer 애니메이션** — 업무 화면에서는 산만하다. 느린 pulse까지만
- **조회할 때마다 화면 전체 딤** — 필터를 연속으로 바꾸는 작업이 매우 답답해진다

#### 깜빡임 방지 — 시안에는 안 보이지만 반드시 전달할 규칙

- **400ms 지연 후 등장** — 빠른 응답에는 인디케이터가 아예 뜨지 않게 한다
- **한번 떴으면 500ms 유지** — 번쩍이고 사라지면 오류처럼 보인다

> 두 규칙이 없으면 아무리 잘 그린 로딩 UI도 실제 화면에서는 깜빡임으로만 보인다. 핸드오프 노트에 꼭 적을 것.

## 04. 로딩 패턴 카탈로그

### A. 테이블 스켈레톤

행 높이·컬럼 폭을 실제 테이블과 똑같이. 기본 10행.
**테이블 헤더는 회색 막대가 아니라 진짜 헤더**를 그린다 — 컬럼이 뭔지 미리 읽을 수 있다.

### B. 영역 스피너 (재조회)

보던 데이터는 그대로 두고 흐리게(불투명도 50%, 흰색 딤 55%). 스피너 24px 중앙.
필터·페이지네이션은 **비활성이되 사라지지 않게** 그린다.

### C. 버튼 인라인 스피너

스피너가 들어가면 버튼 폭이 늘어나 옆 버튼이 밀린다 → **버튼 최소 폭을 시안에 명시**.
확인 버튼만 잠그고 **취소는 살려둔다**. 모달의 ESC·딤 클릭 닫기는 이 동안 차단.

### D. 프로그레스 (진행률 확정)

퍼센트만 두지 말고 **지금 무슨 단계인지**와 건수를 함께 표기 —
`2/3 · 지번 매핑 중` / `64%` / `1,280 / 2,000건 처리`.
5초 이상이면 **취소 버튼 필수**.

### E. 상단 진행바 (화면 이동)

헤더 바로 아래 3px. 화면을 가리지 않는다.
메뉴를 눌렀는데 아무 반응이 없어 보이는 문제를 이것 하나로 해결한다.

### F. 상태 표시 (자동 갱신)

주기적으로 갱신되는 값에 스피너를 쓰면 화면이 계속 깜빡인다. **마지막 갱신 시각**만 보여준다.
`● 실시간 수신 중 · 마지막 갱신 07:41` → 끊기면 점을 회색으로 바꾸고 "연결 끊김 · 재연결 시도 중".

## 05. Empty — 비어 있는 화면 4유형

"데이터 없음" 한 줄로 끝내지 않는다. 비어 있는 **이유**가 다르면 사용자가 해야 할 **다음 행동**도 다르다. 유형을 먼저 구분한 뒤 문구와 버튼을 정한다.

| 유형 | 언제 | 문구 · 다음 행동 |
|---|---|---|
| 최초 빈 상태 | 아직 아무도 등록하지 않음 | "등록된 논리지번이 없습니다" + **등록 버튼(강조)**. 4유형 중 유일하게 CTA를 오렌지로 |
| 검색 결과 없음 | 필터·검색 결과 0건 | "검색 조건에 맞는 지번이 없습니다" + **조건 초기화**. **적용 중인 조건을 그대로 보여준다** — 뭘 바꿔야 할지 알 수 있게 |
| 조회 전 | 조건을 넣어야 결과가 나오는 화면 | "조회 조건을 선택한 뒤 조회 버튼을 눌러 주세요". **오류처럼 보이지 않게** 중립 톤·아이콘 |
| 권한 없음 | 볼 수 있는 계정이 아님 | "열람 권한이 없습니다. 관리자에게 문의해 주세요" + 문의 경로. **재시도 버튼을 넣지 않는다** — 눌러도 달라지지 않음 |

**그리기 규격** — 영역 최소 높이 웹 240px / 모바일 200px (데이터가 있을 때와 높이가 비슷해야 화면이 튀지 않는다). 아이콘 48px `#C6C6C6`, 제목 14px Bold, 설명 12px, 중앙 정렬. 일러스트·이모지는 쓰지 않는다.

## 06. Error — 실패를 알리는 6단계

오류 화면은 **영향 범위**에 맞춰 크기를 정한다. 작은 실패에 큰 모달을 띄우면 사용자는 곧 오류를 읽지 않게 된다. 어떤 방식이든 **무엇이 실패했는지 · 왜 · 지금 뭘 하면 되는지** 세 가지는 항상 담는다.

| 표현 | 쓰는 경우 | 붙일 버튼 |
|---|---|---|
| 필드 인라인 | 입력값이 잘못됨. 해당 필드 아래, 보더 red | 없음(수정 유도) |
| 폼 상단 배너 | 여러 필드가 한꺼번에 틀림 — 요약 후 첫 항목으로 이동 | 항목 바로가기 |
| 영역 오류 | 목록·맵을 못 불러옴. **그 영역만 대체하고 나머지는 살린다** | 다시 시도 |
| 토스트 | 가벼운 실패. 4초 뒤 자동으로 사라짐 | 재시도 / 실행 취소 |
| 모달 | 사용자가 선택해야 끝나는 실패(동시 수정 충돌, 세션 만료). **남발 금지** | 선택지 2개 |
| 전체 화면 | 화면 자체를 열 수 없음. 없는 지번, 네트워크 단절 | 새로고침 / 목록으로 |

### 6-1. 자주 만나는 실패 상황별 화면

| 상황 | 화면 처리 |
|---|---|
| 결과가 0건 | 오류 아님. **Empty로 분기** — 빨간색·경고 아이콘을 쓰지 않는다 |
| 입력값이 틀림 | 필드 인라인. 어떤 형식이어야 하는지 **예시를 함께** — "예) A-12" |
| 로그인 만료 | 모달로 알리고 로그인으로. **작성 중이던 내용은 보존**하고 돌아왔을 때 복원 |
| 권한 없음 | Empty(권한) 유형. 재시도 버튼 없음, 문의 경로 제공 |
| 없는 데이터로 진입 | 전체 화면 오류 + "목록으로 돌아가기". 뒤로가기만 남기지 않는다 |
| 다른 사람이 먼저 수정 | 충돌 모달 — "다른 사용자가 먼저 수정했습니다" + **최신 내용 보기 / 내 내용으로 덮어쓰기** 선택. 여러 명이 같은 지번을 만지는 업무라 반드시 설계 |
| 서버 오류 | 영역 오류 + 다시 시도. **오류코드를 작게 병기** — 현장에서 전화로 문의할 때 필요 |
| 응답이 아주 느림 | 조회는 조용히 재시도 후 오류. **저장·배차 같은 쓰기 작업은 자동 재시도하지 않는다** — 중복 생성 위험 |
| 현장 네트워크 끊김 | 모바일 상단 고정 배너 "오프라인 · 연결되면 자동 전송". 입력한 내용은 보관했다가 자동 전송 |

### 6-2. 오류 문구 작성 규칙

- 개발 용어·서버 원문 메시지를 그대로 노출하지 않는다. 사람 말로 옮기고 **오류코드만** 작게 남긴다
- 사용자를 탓하지 않는다 — "잘못 입력했습니다" → "지번코드 형식이 올바르지 않습니다. 예) A-12"
- "오류가 발생했습니다" 단독 금지 — **무엇이** 실패했는지 대상을 밝힌다
- 되돌릴 수 없는 작업(삭제·배차 확정)의 실패는 토스트가 아니라 **모달**로 확실히 알린다
- 느낌표·이모지를 쓰지 않는다. 현장 업무 시스템의 신뢰도를 떨어뜨린다

## 07. 화면별 적용 매트릭스

시안을 그릴 때 이 표에서 해당 행을 찾아 그대로 적용한다. 새 화면을 추가할 때는 이 표에 행을 먼저 추가하고 시작할 것.

| 화면 / 동작 | Loading | Empty | Error |
|---|---|---|---|
| 지번 목록 최초 진입 | 테이블 스켈레톤 10행 | 최초 빈 + 등록 CTA | 영역 오류 + 다시 시도 |
| 조회·필터·정렬 | 기존 데이터 흐리게 + 영역 스피너 | 결과 없음 + 조건 초기화 | 토스트 + 이전 결과 유지 |
| 페이지 이동 | 동일 (헤더·페이지네이션 유지) | — | 토스트 + 이전 페이지로 복귀 |
| 도면·맵 렌더링 | 맵 영역 스켈레톤 + "도면을 불러오는 중입니다" | "등록된 영역이 없습니다" | 영역 오류 + 재로드 |
| 등록·수정 팝업 저장 | 버튼 인라인 스피너, 닫기 차단 | — | 필드 인라인 + 폼 상단 배너 |
| 삭제 확인 팝업 | 확인 버튼만 로딩, 취소는 활성 | — | 모달 내 오류 배너 (팝업 유지) |

## 09. 표준 문구 사전

같은 상황에 매번 다른 문장을 쓰지 않기 위한 사전. `{대상}`에 화면의 대상어(지번, 블록, 배차 등)를 넣어 쓴다.

| 상황 | 표준 문구 |
|---|---|
| 조회 중 | 불러오는 중입니다 |
| 저장 중 | 저장 중 (버튼 라벨은 말줄임표 없이) |
| 저장 성공 | 저장되었습니다 |
| 삭제 성공 | 삭제되었습니다 (+ 실행 취소 5초) |
| 최초 빈 상태 | 등록된 {대상}이 없습니다 |
| 검색 0건 | 검색 조건에 맞는 {대상}이 없습니다 |
| 조회 전 | 조회 조건을 선택한 뒤 조회 버튼을 눌러 주세요 |
| 조회 실패 | {대상}을 불러오지 못했습니다. 잠시 후 다시 시도해 주세요 |
| 저장 실패 | 저장하지 못했습니다. 입력 내용을 확인해 주세요 |
| 권한 없음 | 열람 권한이 없습니다. 관리자에게 문의해 주세요 |
| 세션 만료 | 로그인이 만료되었습니다. 다시 로그인해 주세요 |
| 동시 수정 충돌 | 다른 사용자가 먼저 수정했습니다. 최신 내용을 확인해 주세요 |
| 오프라인 | 오프라인 상태입니다. 연결되면 자동으로 전송됩니다 |
| 장시간 작업 | 처리 중입니다. 완료되면 알림으로 알려 드립니다 |

## 10. 개발 전달 시 함께 적어야 할 것

시안 이미지만으로는 전달되지 않는 항목이다. 화면 옆 노트나 스펙 코멘트로 반드시 남긴다.

| 전달 항목 | 적을 내용 |
|---|---|
| 등장·유지 타이밍 | "400ms 이후 등장, 최소 500ms 유지" — 전 화면 공통 |
| 잠기는 범위 | 어느 영역까지 비활성인지 시안에 명시. 특히 **필터·취소 버튼은 살아 있어야 함** |
| 재조회 시 동작 | "기존 데이터 유지 + 흐리게" — 스켈레톤으로 대체하지 말 것 |
| 높이 고정 | 상태가 바뀌어도 영역 높이가 변하지 않도록 최소 높이 지정 |
| 중복 실행 방지 | 저장·배차 버튼 연타 시 **한 번만 실행**되어야 함을 명시 |
| 문구 원문 | Empty·Error 문구를 시안에 텍스트로 확정 (개발자가 짓지 않도록) |
| 접근성 | "스크린리더가 로딩·오류를 읽을 수 있게" · "모션 최소화 설정 시 회전 정지" |

## 11. 디자인 리뷰 체크리스트

화면을 "완료"로 넘기기 전 확인한다. 하나라도 미충족이면 완료가 아니다.

- [ ] Loading·Empty·Error 시안이 모두 있음
- [ ] Empty가 4유형 중 어디에 해당하는지 정해짐
- [ ] 로딩 중 잠기는 범위가 시안에 표시됨
- [ ] 재조회할 때 보던 데이터가 사라지지 않음
- [ ] 세 상태의 영역 높이가 같아 화면이 튀지 않음
- [ ] 모든 Empty·Error에 다음 행동이 있음
- [ ] 문구가 사전 기준을 따르고 개발 용어가 없음
- [ ] 상태를 색만이 아니라 텍스트로도 알림
- [ ] 데이터가 많을 때·글자가 길 때도 확인함
- [ ] 모바일은 야외 가독성·장갑 터치를 고려함

## 12. 목업 적용 현황 (2026.07.28)

지번관리 화면군(HEL02~HEL04, 35개 화면)은 모두 `지번관리.dc.html` 하나를 불러쓰므로 공통 상태 처리를 한 번에 적용했다. API 연동 전이므로 아래 지연 시간을 가정한 가짜 응답으로 동작한다.

| 동작 | 가정 지연 | 적용한 패턴 |
|---|---|---|
| 화면 진입 | 800ms | 테이블 스켈레톤 10행(헤더 유지) · 지도 화면은 3단 스켈레톤 + "도면을 불러오는 중입니다" |
| 조회 · 필터 재조회 | 1,200ms | 기존 데이터 유지 + 흰색 딤 55% + 영역 스피너 24px · 필터는 계속 조작 가능 |
| 등록 · 수정 · 삭제 저장 | 900ms | 확인 버튼 인라인 스피너 + "저장 중" · 연타 1회 제한 · 취소 버튼은 활성 유지 |
| 엑셀 업로드 | 6,000ms | 프로그레스 6px + 단계 표기(1/3 파일 검증 → 3/3 저장) + 건수 + 취소 버튼 |
| 메뉴 이동 | 700ms | 헤더 아래 상단 진행바 3px · 화면을 막지 않음 |

**Empty 4유형**은 Tweaks 패널의 **상태 UI › 빈 상태**에서 전환해 리뷰한다(최초 빈 상태 / 검색 결과 없음 / 조회 전 / 권한 없음). 로딩 화면을 멈춰두고 보려면 **상태 고정**을 쓴다.

**Error는 동작에 넣지 않고** 정적 시안 `HEL90-01 상태 시안 (오류).dc.html`로 분리했다 — 6단계 오류 표현과 오프라인·수신 끊김·세션 만료 배너를 담았다.

### 12-1. 깜빡임 방지 · 성공 알림 · 접근성 (2026.07.28 보완)

| 가이드 항목 | 목업 구현 |
|---|---|
| 400ms 지연 등장 · 500ms 최소 유지 (§03, §10) | 재조회·저장 인디케이터에 적용. 400ms 안에 끝나면 아예 뜨지 않고, 떴으면 500ms를 채우고 사라진다. 최초 진입 스켈레톤은 대체할 내용이 없어 즉시 노출(깜빡임 위험 없음) |
| 중복 실행 방지 (§10) | 스피너 등장 여부와 무관하게 저장·삭제는 1회만 실행 (지연 400ms 구간의 연타 포함) |
| 저장·삭제 성공 문구 (§09) | 토스트 — "저장되었습니다" 4초 · "삭제되었습니다" 5초 + **실행 취소** 버튼 |
| 접근성 (§10) | 화면당 `aria-live="polite"` 안내 영역이 로딩·저장·업로드 진행률·토스트를 읽어 준다. 모션 최소화 설정 시 스피너·pulse·진행바 회전 정지 |
| 응답 속도 검증 | Tweaks 패널 **상태 UI › 응답 속도** — 빠름(0.25×) / 보통 / 느림(2.5×). **빠름**으로 두면 400ms 지연 등장 규칙이 실제로 동작하는 것을 확인할 수 있다 |

> 남은 항목 — 조회 실패·서버 오류 토스트는 목업 동작에 넣지 않았다(정적 시안으로 대체). 실 API 연동 시 §07 매트릭스의 Error 열을 그대로 붙이면 된다.
